Buy or Wait?

A financial decision agent built in 24 hours. For each of 250 purchase requests, it reconstructs the user's 90-day financial position and answers: can they afford this, and how?

Core principle: the model perceives — it reads image amounts and message intent. Deterministic code decides — it runs the 90-day forecast and applies every rule. The model never names an affordability verdict, writes a payment plan, or generates an explanation.

What we did not measure
We did not measure payment_plan or spending_changes_needed accuracy — the self-test script compares only the four fields above. We also did not measure decision_explanation quality, which the problem statement says is scored. Our explanations are grounded in actual event IDs and never written by the model.
Trace: request_08

A step-by-step walkthrough of one request through all three stages. This request exercises the message-parse guardrail: a salary amendment arrives with no linked event.

Input: user_08 · EUR 996.60 repair · request_date 2025-02-07 · desired_completion 2025-04-15 · allows_partial_payment: false
S1
Stage 1 · load_inputs.py
Parse, OCR, merge
No image — user_08 has no linked image, so Stage 1b (OCR) is skipped. evidence_complete stays True.

Message parse — message_06 is linked to user_08. The model reads: "Hi, Greenfield Foods payroll here. Your next salary is reduced to EUR 1422.85." It returns {"intent": "amend", "new_amount": 1422.85, "new_date": null}. Parse succeeds and is cached by SHA-256.

Amendment not applied — _apply_messages looks for related_event_id on message_06. The field is blank. No event row is updated. The parse result is logged but the financial data is unchanged.

Why no error? The recurring pattern detector later computes a median salary of EUR 1,422.85 from the last six settled payments — which already matches the amended amount. The silent skip caused no forecasting error in this case.
S2
Stage 2 · forecast.py
90-day balance projection
Start balance: EUR 1,536.57 · minimum balance: EUR 800.

Recurring patterns detected: salary EUR 1,422.85/month on the 15th, rent EUR 467.50/month, groceries EUR 72.38/week, debt repayment EUR 177.00/month.

Result: 54 projected cash flows from 2025-02-07 to 2025-05-09. The minimum projected balance over the 90-day window — without any payment — is EUR 1,070.65, reached before the March salary.
amount_safe_to_pay = 1,070.65 − 800 = 270.65 270.65 < 996.60 → full payment today is not safe
S3
Stage 3 · decide.py
Decision priority walk
Full payment today? EUR 270.65 < EUR 996.60 → fail.

Installments? user_08 accepts installments. All available installment last-payment dates fall after 2025-04-15. None pass the horizon check → fail.

Wait? Scan each cash-flow date. On 2025-04-15, salary credit of EUR 1,422.85 arrives. Suffix minimum from that date onward: EUR 1,796.60. EUR 1,796.60 − EUR 996.60 = EUR 800.00 ≥ minimum balance → pass.

Result: affordable_later / wait. earliest_date_for_full_payment = 2025-04-15, which exactly equals desired_completion_date.
