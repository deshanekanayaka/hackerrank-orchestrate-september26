## Strategy We Tried and Rejected: Extended Interval Buckets

We added two new interval buckets: 10-day (for patterns between 9 and 12 days) and 21-day (for patterns between 17 and 24 days).

Result before: requests 03 and 18 had wrong `earliest_date_for_full_payment`. The code missed 10-day and 21-day recurring expenses. It did not reserve those amounts in the 90-day balance projection.

Result after (monkey-patch test, not committed): requests 03 and 18 were fixed (+2 fields). Requests 02, 11, and 25 were broken. User 25 lost `amount_safe_to_pay` (went from 1,443,216 to 0) because the 10-day bucket projected a grocery expense on Mar 9 that gold does not project. Gold's reason for skipping that projection is unknown. Net: -4 fields. We reverted.

## What We Did Not Measure

We did not measure `payment_plan` accuracy or `spending_changes_needed` accuracy. The self-test script compares only the four fields above. We also did not measure `decision_explanation` quality, which the problem statement says is scored. We know from manual inspection that our explanations are grounded in the actual event IDs used in the forecast and not generated by the model.
